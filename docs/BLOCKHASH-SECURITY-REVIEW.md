# 区块哈希候选版逻辑与安全检查

检查日期：2026-09-15。范围：BnbfishBlockhash 合约、独立构建、测试、未签名部署候选文件。不是独立第三方审计，不表示已经上线或已经完成主网闭环。

## 实现和检查结论

| 项目 | 结果 |
| --- | --- |
| 200 万累计发行上限、五档及 100 物种配额 | 构造校验及最后一枚边界测试通过；无增发/改配额入口 |
| 每 10 区块固定目标哈希 | 不接受调用者提供随机数；测试直接读取目标区块并独立计算种子及获鱼记录 |
| 持续垂钓 | 未获鱼记录继续参与，获鱼只移除对应一条记录，重复抛竿独立计数 |
| 后知哈希加入或收竿 | 到期冻结成员变更；等待至少 10 区块才具备资格 |
| 分批或调用者选择结果 | 45 条记录以 7 和 20 条分批得到相同获鱼记录；无全历史重复扫描 |
| 重复发鱼 | 顺序推进目标，成功后目标前移；两次实际铸造至少间隔 10 区块 |
| 恶意接收合约阻塞 | 铸造不触发接收回调；拒绝接收回调的测试合约不阻塞推进 |
| 哈希失效 | 保存过的哈希长期可用；缺失且过期时明确记录超时，不重抽，不伪造空竿 |
| 暂停权限 | 仅影响新抛竿；不能改变结果、阻止既有处理或 ERC-721 转账 |
| 原版隔离 | 仅独立候选目录输出；原 VRF 合约、主网地址和运行中 keeper 未替换 |

测试环境：Ganache，本地 chainId 1337；非 BNB 主网结果。5 个测试用例包含上述多项断言。45 条记录场景内，单次 20 条成熟资格处理观测最高 1,537,856 Gas，此数值不是所有状态下的绝对上限，也不是 BNB 金额。独立构建运行时代码 14,845 字节，低于 EIP-170 限制。

## 仍然成立的风险和运行限制

1. **出块者影响随机结果。** 未来哈希不是 VRF，不能声称绝对公平或绝对不可操纵。三个区块深度只减少短期波动，不提供额外共识最终性。
2. **推进可用性及选择性不提交。** 所有推进者若不保存某节点哈希，该节点超过 256 区块后会跳过；运营方可能通过不提交影响实际产出。公开入口能降低独家依赖，但不能消除此风险。
3. **Gas 消耗和拥堵。** 无 VRF 服务费仍有每个有效节点的推进费。重复抛竿被明确允许，增加机会也增加资格处理成本；大量请求可能拖慢服务、耗尽预算。没有无限吞吐或绝对准点承诺。
4. **收竿暂时受队列约束。** 到期后不能立即修改成员，网页必须显示正在确认并自动等待。长期积压时恢复队列需要多笔交易。
5. **旧版和新版权益不同。** 新地址有独立 200 万上限。旧地址的待确认 VRF 仍可能产出，不能把两个地址的总量称作单一 200 万集合。暂停旧版不取消旧请求。
6. **图片并未永久上链。** 链上存储鱼种、稀有度、尺寸、品质和 URI；当前 HTTPS 图片服务可改变图片内容。
7. **智能合约钱包兼容性。** 无回调铸造防止全局阻塞，但收鱼合约必须自行支持 NFT 管理；普通 EOA 和可管理 ERC-721 的智能钱包可通过标准接口转移。

## 切换前的交付门槛

- 网页与自动推进服务接入新的 ABI、持久垂钓状态、暂时不能收竿状态和超时状态；当前 read-only action planner 不等同于已运行的新 keeper。
- 保留旧地址记录，核验供应量和待处理 VRF，再由用户钱包签名暂停旧版新抛竿。
- 新部署候选文件包含完整创建数据及哈希；部署、开启需要用户钱包签名，尚未发送任何部署交易。
- 部署后逐项核验字节码、构造参数、所有 100 个配额及权限，观察一次真实抛竿到转移的闭环后再切网站默认地址。
- 监控推进延迟、未保存哈希剩余时间、Gas 预算及错误；在没有这些监控前不作为正式运营版本。

当前候选已通过本地逻辑检查，可以继续做新版接入；以上残余风险不能用“智能合约不可篡改”一句话代替说明。
